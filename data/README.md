# Data layout

Place the precomputed inputs in the following locations. The filenames are part
of the interface used by the existing modeling code.

```text
data/
├── features/
│   └── <VARIABLE>_features_time2000.nc
├── metrics/
│   └── <VARIABLE>_quality_metrics_time2000.nc
├── precomputed_labels/              # generated by precompute_labels.py
├── source_data_time2000/
│   └── lens1_ens25_1920/
│       ├── orig/
│       ├── zfp_p_8/
│       ├── zfp_p_10/
│       ├── zfp_p_12/
│       ├── zfp_p_14/
│       ├── zfp_p_16/
│       ├── zfp_p_18/
│       ├── zfp_p_20/
│       ├── zfp_p_22/
│       ├── zfp_p_24/
│       └── zfp_p_26/
└── runs/                            # timestamped model and plot outputs
```

Each source-data directory contains files named like:

```text
b.e11.B20TRC5CNBDRD.f09_g16.025.cam.h1.<VARIABLE>.19200101-20051231.nc
```

Feature files must contain `feature_values` indexed by `collection`, `feature`,
and `timestep`. Metric files must contain `quality_metric_values` indexed by
`collection`, `compression`, `timestep`, and `metric`, with the
`quality_requests` metadata written by the current metric-generation workflow.
The first 2,000 metric timestep coordinates must be `1..2000`.
